# Full-release content delivery

The current release has **395 guides / 13,449 teaching fields**. Its encrypted envelope is **6,113,247 bytes**, manifest **6,567,779 bytes**, and availability file **8,767 bytes**. The selected authenticated response is a different payload. Each request freshly validates session/current educator authority, then decrypts, parses and validates the full release before returning the selected plan. Benchmark requests additionally load legacy benchmark guidance. No cache or packaging change was made.

The standalone fallback still requests the complete lesson catalogue for navigation. An [earlier genuine 395-guide comparison](catalog-comparison.json), with identical released content and server API code, returned 101,791 decoded bytes with the catalogue versus 20,092 without it for the same lesson. Its five-per-mode timings have different request order/conditions and do not isolate a causal latency saving. The current normal-reader measurements in this report use catalogue omission.

[Normal samples](normal-delivery.json), [hosted samples](hosted-delivery.json), [local 395](local-395.json), [local 24](local-24.json) and [summary](SUMMARY.json) preserve actual values. All responses match released hashes and retain private/no-store. [Enabled](diagnostic-enabled-access.json) and [disabled](diagnostic-disabled-access.json) genuine-role checks distinguish measurement authority from ordinary educator access. [Cleanup](diagnostic-cleanup.json) and [normal build/public scan](normal-build-verification.json) confirm normal protected delivery after removing temporary instrumentation. No plaintext guide or key is published.

The selected normal response is already much smaller than the server release. Repeated sequential full-plan validation takes a median 110.39 ms, while normal request latency has a median 884.0 ms including fresh Auth, network and serialization. These are different measurement paths; subtracting them does not isolate Auth cost or attribute every delay to guide size. Keep the current secure delivery for owner review. Next, compare a bounded server-process cache keyed by immutable release digest/version against smaller authenticated lesson/term envelopes bound to versioned source/lesson/schema manifests, with separate Auth/network timing. This is a separately reviewed staging experiment, not an immediate production change. Preserve the original key, authenticated integrity and fresh session/current-role checks before every response. A cached plan must never cache permission, leak between institutions or survive a release update under an old identity. Test concurrent initial loads, eviction/memory bounds, release invalidation and live revocation. Smaller releases trade parsing/import size against packaging/file overhead; a cache trades retained memory against repeated work. These observations do not select an optimal chunk size or establish multi-user capacity. Database migrations and production architecture changes remain separately subject to owner approval.

The earlier [237-plan measurements](../../staging-classroom-validation/pr79-followup/PERFORMANCE.md) used different content, request order, roles and runtime conditions. They do not isolate a release-size causal trend. First measured requests and local first calls are not guaranteed cold processes, and repeated requests do not demonstrate a cache hit in the current uncached loader.
