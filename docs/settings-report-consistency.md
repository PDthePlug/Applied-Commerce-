# Settings and cross-role progress consistency

Continuation of the master hardening directive, 17 October 2026 (Africa/Johannesburg). This increment builds on merged PR #36. Overall readiness remains **NOT PRODUCTION READY** until the outstanding business-rule, email and operational gates are verified.

## Verified defects and corrections

| Severity | Root cause | Correction and affected modules |
|---|---|---|
| P1 | Facilitator completion counted every saved ID, including assessments, retired content and other grades. Every roster row used the selected learner's denominator. | `lib/facilitator/model.ts` uses the current catalogue for the learner's current grade and supplies its own lesson total/percentage. The workspace uses each row's denominator, and reads current remote records directly rather than committing an older selection through an async effect. |
| P1 | Administrator lesson totals counted all completed progress rows. | Institution insights count only current catalogue lesson IDs, retaining the existing aggregate across the active learners' grades. Assessments/history remain stored and do not become lessons. No assessment approval or cohort-grade rule was added. |
| P1 | Profile hydration changed the component key and destroyed an unsaved field; once a profile existed, initial React state could instead hide later saved values. | Profile forms are keyed by account. Draft fields overlay current saved props only after the user edits them; successful local saves clear the draft. Untouched fields can refresh while unsaved fields survive. |
| P2 | Some facilitator authorization/roster/profile queries still stopped at API row caps. Other large UUID filters could exceed URL limits even when result pagination existed. | Stable pagination throughout the affected facilitator loaders/role gate and institution loaders. Shared `readRowsByIds` deduplicates and batches filters at 100 IDs, paginates each batch at 500 rows, and rejects the whole read on a failed page/batch. RLS and release/ownership predicates remain in the queries. |
| P2 | A rejected catalogue or grade promise stayed in the shared cache for the rest of the page session. | Evict only the failed cache entry. Successful requests remain shared; later retries can fetch again. The facilitator catalogue has a recoverable loading/error state. |
| P2 | Dark/system preferences changed inherited text to light while staff cards, forms and review surfaces stayed white. A facilitator heading measured 1.11:1 contrast. | Staff component rules use theme surface/copy tokens with their original light colours as fallbacks. Explicit paired status/primary colours remain intact. Screen-only dark/system tokens cover facilitator and institution operations. |

## Verification and limits

The old production build reproduced the profile draft-loss regression. The old staff CSS also failed a contrast regression. After correction, all 15 local settings checks passed across 1280px, 430px and 360px, including cross-tab dirty/pristine profile fields and explicitly labelled staff CSS fixtures in dark/system mode. Those fixtures are not authenticated role workflow coverage. Local Node tests: **159 passed, zero failed/skipped**. Lint and production build passed. Dedicated mocked query tests retain 1,201 learners for both assigned-facilitator and platform-administrator paths and verify bounded ID filters. These are API-cap regressions, not a hosted capacity or latency certification.

The signed role suite now tests real two-device account preferences through the Next.js preferences API: partial patches, reload, failed-write rollback/retry, global sign-out, stale-account 409 denial and account isolation. It also tests facilitator/school-admin/platform-admin preference persistence and cross-device learner profile refresh through normal account APIs. The reporting suite retains two lessons, an assessment and a historical completion, then checks administrator totals and per-grade roster/report values. Run using dedicated isolated fixtures and an exact hosted commit, as documented in `reporting-workspace-hardening.md`. Final hosted results and deployment evidence belong in the external engineering report; the presence of these tests is not a PASS.

No dependency or database migration is introduced. No credentials are committed. No email is sent. Existing immutable review ownership is preserved; replacement-reviewer policy, actual verification/recovery email delivery, alert delivery, hosted capacity, historical migration reconciliation and broader inventory/accessibility/reporting coverage remain open.
