# Actual private-content delivery measurements

The release contains **237 plans / 8,840 teacher fields**. Each request still performs fresh user/session/role checks, then opens and validates the full encrypted teaching release before selecting one plan. Benchmark lessons additionally load the original benchmark guidance. Responses remain private/no-store. No cache or packaging architecture change is implemented.

| Measurement | Observation | Practical limit |
| --- | --- | --- |
| Normal PR #79 delivery | 120 sequential requests across the original 24 guides; median 874.5 ms, range 633–1,514 ms; 12,205–70,344 decoded bytes | Proxy-observed end-to-end requests; response size differs by lesson and benchmark payload |
| Bounded normal overlap | Three waves of four requests; wall times 1,048 / 1,082 / 1,160 ms; all twelve responses match release hashes | One educator account and low volume; no capacity claim |
| Hosted first private-content reads | Two sequential route instances: private-read stages 491.7 / 496.6 ms, including imports 294.6 / 323.1 ms and plan loading 196.9 / 173.3 ms | Process uptimes were 75.5 s and 2.1 s. These are observed first content reads; platform cold bootstrap is not isolated |
| Hosted repeated reads | Thirteen sequential repeats across those instances: median private-read stage 77.65 ms; plan stage 77.55 ms | Excludes Auth and response serialization; includes elapsed work/queuing inside that stage |
| Hosted memory | Across 27 instrumented requests, three route instances: observed RSS snapshots 103,575,552–277,368,832 bytes (about 98.8–264.5 MiB) | Actual Node process memory, including other work and GC. Not a per-request retained allocation or platform peak-memory metric |

[Raw hosted observations](hosted-delivery.json), [summary](delivery-summary.json), [normal requests](baseline-delivery.json), [local 237-plan observations](local-237-benchmark.json) and [local subset](local-24-benchmark.json) preserve samples. All authenticated responses are checked against exact released plan hashes. The local reconstruction comes from genuine authorised API inspection and does not export the server key.

The platform memory-query API requires Observability Plus (HTTP 402). The temporary diagnostic instead used the existing private route after fresh authorisation, an additional current platform-admin check, an explicit server flag, exact staging Vercel project and exact staging Supabase URL. It returned only numerical process/timing metadata and an opaque route-instance identifier alongside the administrator's already-authorised response. Normal requests contain no diagnostics. Five genuine roles verify enabled and disabled boundaries. The flag and enabled deployment have been removed; the normal release denies diagnostics even to the platform administrator.

The measured first import and repeated full-release work justify a separately reviewed staging comparison before 395-guide scale. Compare an authenticated per-lesson or small-term envelope bound to an immutable versioned manifest against a bounded process cache keyed by release digest. Preserve the original key, source/lesson/schema identity, authenticated encryption and fresh session/current-role checks before every response. Test version invalidation, concurrent loading, memory bounds and revocation; a cached plan must never cache a permission decision.

Current evidence does not select an optimal chunk size or demonstrate that caching is necessary. It shows approximately 78 ms of repeated server-side plan loading and a larger first import, while complete request latency also includes authorisation/network/proxy work. Do not attribute that whole latency to decryption, infer retained memory from heap deltas, or extrapolate capacity to the remaining guides. Database migrations and production architecture changes remain separately scoped for owner approval.
